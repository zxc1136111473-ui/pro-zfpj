## 二、踩过的坑与解法(按顺序)

### 坑 1:OOM 杀进程
**现象**:install.sh 拉完镜像后 docker-compose(python)被 oom-killer 杀掉。
**根因**:生产机 3.8G 内存已用 2.4G,ZeroForwarder 全栈拉起必然 OOM。
**解法**:停掉工具类容器释放内存:
```bash
docker stop comfyui infinite-canvas   # 释放 ~520MB, 可用 1.3G→2.1G
```

### 坑 2:80/443 被系统 caddy 占用
**现象**:install.sh 端口检查报 `80 443 被占用` 退出码 11。
**根因**:CADDY_ENABLED 默认 true,检查 80/443。
**解法**:`CADDY_ENABLED=false`(zf-web 走 8080, controler 走 3100)。

### 坑 3:官方 install.sh 卡死(低内存机)
**现象**:bash -x 追踪显示卡在 `guard_fresh_install` 后,`docker ps --filter` 后 hang,
多次重试同样位置,CPU 0%,日志停在镜像预拉取。
**根因**:疑似低内存/慢 IO 下 bash 内建+子进程组合挂死(未完全定位)。
**解法**:绕过 install.sh,手动分步执行等价流程(generate-key → .env → compose → up)。

### 坑 4:mock 密钥文件名不匹配
**现象**:mock 容器报 `FileNotFoundError: '/keys/pub.pem'`。
**根因**:部署脚本生成 `mock_rsa_pub.pem`,mock 代码读 `/keys/pub.pem`。
**解法**:软链标准文件名:
```bash
ln -sf mock_rsa_priv.pem priv.pem && ln -sf mock_rsa_pub.pem pub.pem
```

### 坑 5:公钥指纹算法错误
**现象**:`Token invalid: Fetched public key does not match any trusted fingerprint`。
**根因**:`ZFC_AUTH_TRUSTED_PUBKEY_SHA256` 期望的是 **DER 编码的 sha256**,
不是 PEM 文本的 sha256。
**解法**:
```bash
DER_SHA=$(openssl rsa -pubin -in mock_rsa_pub.pem -outform DER | sha256sum | cut -d' ' -f1)
# 写入 .env: ZFC_AUTH_TRUSTED_PUBKEY_SHA256=$DER_SHA
```

### 坑 6:JWT 缺 sid 字段
**现象**:`Token invalid: Token verification failed: JSON error: missing field 'sid'`。
**根因**:JWT payload 反序列化需要 `sid`(session id)字段。
**解法**:JWT payload 加 `"sid":"mock-session-001"`。

### 坑 7:DB schema 门禁
**现象**:`failed to read ZfcSchemaState; upgrade with the current install.sh`。
**根因**:手动部署跳过了 prisma 迁移,ZfcSchemaState 表不存在/无记录。
**解法**:
```bash
# 1) 抽 schema 并按 schema 建表
docker cp zf-schema-extract:/app/schema-bundle/schema.prisma ./prisma/schema.prisma
docker run --rm --network zf_default -v /opt/zf/prisma:/app/prisma \
  -e DATABASE_URL=... hub.covm.net/zfc-prisma:latest npx prisma db push --accept-data-loss
# 2) 插入 ZfcSchemaState 主记录 (version=1.2.0, 用 manifest.env 的 sha + 镜像 digest)
```

### 坑 8:worker 二进制缺失
**现象**:`No worker binary found and version query failed. Cannot proceed.`,
healthcheck 一直 starting,zf-web 拒绝启动。
**根因**:controler 需要 zf-worker/forwarder-server 二进制(默认路径 `./worker/zf-worker`,
`./forwarder/forwarder-server`),本地没有才去授权服务器下载;mock 下载端点不完整。
**解法**:用离线包的 `server` 二进制顶替:
```bash
mkdir -p /opt/zf/worker /opt/zf/forwarder
cp /opt/zf-node/server /opt/zf/worker/zf-worker
cp /opt/zf-node/server /opt/zf/forwarder/forwarder-server
# compose 挂载 + env:
#   WORKER_BINARY_PATH=/worker/zf-worker
#   FORWARDER_BINARY_PATH=/forwarder/forwarder-server
```
**效果**:`Using existing forwarder binary despite version query failure` + `Forwarder version: 1.1.67`。

## 三、授权协议关键结论(实战确认)

1. **响应包裹**:`{"success":true,"data":{...}}`(public-key / heartbeat 均如此)
2. **公钥指纹**:DER(SPKI)sha256,不是 PEM 文本 sha256
3. **JWT payload**:至少需要 `sub` + `sid` + `iat` + `exp` + `mode` + `entitlements`
4. **worker-version**:`GET /instance/{id}/worker-version?controller_version=X&arch=Y`,
   响应结构包含 `total_size/chunk_size/decoded_size/chunk_index/is_last/download_url`(分块下载协议);
   本地已有 worker 时版本查询失败**不影响启动**(降级重试)
5. **WS 通道**:controler 连 `ws://{auth}/ws/instance/{id}/auth`,需持续 keepalive(每 30s 心跳),
   mock 发一帧就断会导致 `Connection reset`(修复:循环读帧+周期发心跳)
6. **admin 创建**:`zfc-admin add-user --user-file-path /tmp/admin_user.json`(token 登录,无密码)
