## 一、控制面(面板)脚本命令

### 1. 控制面安装脚本

```bash
# 官方源
bash <(curl -sL https://get.zeroforwarder.com/install.sh)

# 自托管源(你的 git, 不依赖官方)
bash <(curl -sL https://raw.githubusercontent.com/zxc1136111473-ui/pro-zfpj/main/zf-rev/deploy/zf_install_selfhost.sh)
```

### 2. 非交互安装(带参数)

```bash
bash <(curl -sL https://raw.githubusercontent.com/zxc1136111473-ui/pro-zfpj/main/zf-rev/deploy/zf_install_selfhost.sh) \
  --install --non-interactive --config /opt/zf/zfc.env
```

### 3. 一键部署脚本(deploy-zf-oneclick.sh, 含 mock 授权)

```bash
sudo ./deploy-zf-oneclick.sh \
  --web-domain forward.example.com \
  --controler-domain zf-ctl.example.com \
  [--instance <uuid>] [--api-key <key>] [--mock-port 9099] \
  [--install-dir /opt/zf] [--caddy-email you@example.com] \
  [--disable-tdengine] [--no-verify] [-y]
```

参数说明:

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `--web-domain` | ✅ | - | 前端域名(zf-web) |
| `--controler-domain` | ✅ | - | 控制器域名(zf-controler) |
| `--instance` | - | 随机 uuid | 授权实例 ID |
| `--api-key` | - | 随机 hex | API 密钥(任意值) |
| `--mock-port` | - | 9099 | mock 授权服务器端口 |
| `--install-dir` | - | /opt/zf | 安装目录 |
| `--caddy-email` | - | 空 | 启用 Caddy/HTTPS 时邮箱 |
| `--disable-tdengine` | - | off | 禁用 TDengine(内存紧张时) |
| `--no-verify` | - | off | 跳过结尾 license 验证 |
| `-y` | - | off | 非交互确认 |

### 4. install.sh 支持的 CLI 动作

```bash
--install        # 安装控制面
--update         # 更新(可加 --to <版本>)
--uninstall      # 卸载(需 ZFC_UNINSTALL_MODE)
--show-token     # 查看管理员 token
--refresh-token  # 刷新 token
--pack           # 打包迁移
--restore        # 恢复(需 ZFC_RESTORE_PACKAGE)
--check          # 检查状态
--doctor         # 诊断
--clean-install  # 清空重装(隐含 --force)
```

### 5. 安装必填环境变量

```bash
WEB_DOMAIN=forward.example.com
CONTROLER_DOMAIN=zf-ctl.example.com
ZFC_INSTANCE_ID=<uuid>
ZFC_API_KEY=<key>
ZFC_VALIDATE_LICENSE=0        # 跳过 license 校验(自建授权必需)
CADDY_ENABLED=false           # 避开 80/443 冲突
TDENGINE_TYPE=disabled        # 省内存
DISABLE_TDENGINE=true
ZFC_AUTH_SERVER_URL=http://zf-mock-auth:9099   # 指向自建 mock
ZFC_AUTH_TRUSTED_PUBKEY_SHA256=<mock DER 指纹>
```

### 6. 控制面运维

```bash
# 服务管理(安装目录 /opt/zf)
cd /opt/zf && docker compose ps
docker compose restart zf-controler zf-web    # 改配置后

# mock 授权服务器
docker logs zf-mock-auth                       # 授权请求日志
/opt/zf/mock-auth/run-mock.sh restart          # 手动重启

# 系统 caddy 站点(德国服务器)
ls /etc/caddy/sites/
systemctl reload caddy                         # 改站点后重载

# 登录面板
# https://zf.artusx.com  (admin@zfc.local + token 见 .admin_token)
```

## 二、服务器端(worker)命令

### 1. 安装(面板生成的安装命令)

```bash
# 面板"添加服务器"给的命令, 从控制面动态生成(pubkey/token 唯一)
curl -s "https://iplcjh.wqyhr.com/worker_setup_script/<pubkey>?token=<token>" | bash -s eth0
```

### 2. 卸载

```bash
curl -s https://iplcjh.wqyhr.com/worker_uninstall_script/<pubkey> | bash
```

### 3. 手动安装(离线包, 国内加速下载)

```bash
# 下载 1.2.0 离线包(国内可用 GitHub 加速)
curl -sL "https://ghfast.top/https://github.com/zxc1136111473-ui/pro-zfpj/releases/download/v1.2.0/zf-worker-offline-x86_64.sh" -o zf-worker.sh
bash zf-worker.sh eth0        # arm64 换 zf-worker-offline-arm64.sh
```

### 4. 手动装二进制(已有 config.json 时)

```bash
curl -sL "https://zfctl.artusx.com/api/worker/download?arch=x86_64&controller_version=1.2.0" -o /root/zf/zf-worker
chmod +x /root/zf/zf-worker && /root/zf/zf-worker --version
```

### 5. 服务管理(worker 装好后)

```bash
systemctl status zf          # 查状态(服务名默认 zf, 可自定义)
systemctl restart zf         # 重启
journalctl -u zf -f          # 看日志
```

### 5. 手动升级(在端点机器上)

```bash
# 定位服务
SVC=$(systemctl list-units --type=service --all | grep -oE "fwd_server_[0-9]+\.service" | head -1)
DIR="/opt/$(echo $SVC | sed 's/.service//')"
# 下载 1.2.0 并替换
curl -sL "https://zf.artusx.com/api/forwarder/download/cb8d003a-9a4a-4657-9193-cfbf946d24cf/server?arch=x86_64" -o $DIR/server.new
chmod +x $DIR/server.new && cp $DIR/server.new $DIR/server
systemctl restart $SVC
```

### 6. 服务管理

```bash
systemctl status fwd_server_1791219399
systemctl restart fwd_server_1791219399
tail -30 /opt/fwd_server_1791219399/server_current.log   # 运行日志
```

## 六、常见排障速查

| 现象 | 处理 |
|---|---|
| 面板端点离线 | 检查端点版本: `/opt/fwd_server_*/server --version` 应为 1.2.0; 控制面挂载 `/opt/zf/forwarder/forwarder-server` 版本一致 |
| 版本降级循环 | 换二进制后重启 zfc-controler + zfc-web; mock version 响应返回 1.2.0 |
| worker 安装 TLS 失败 | 确认 zfctl.artusx.com 已配 caddy 反代到 3100 |
| mock 容器报密钥错误 | 软链: `ln -sf mock_rsa_priv.pem priv.pem && ln -sf mock_rsa_pub.pem pub.pem` |
| license 指纹不匹配 | `ZFC_AUTH_TRUSTED_PUBKEY_SHA256` 用 DER SHA256(openssl rsa -pubin -in xxx.pem -outform DER \| sha256sum) |
| 续费功能报错 | mock 未实现续费端点, 无害(license 10 年期) |

## 八、域名切换后的节点管理(2026-10-06 实测)

### 控制面新域名(66.154.118.133)
- 前端: https://iplcsd.wqyhr.com
- 后端/controler: https://iplcsdhd.wqyhr.com
- 旧域名(iplcjh/iplcjhkzq)已停反代, 不可再用

### 节点 config 由控制面管理(改了会还原!)
**重要机制**: worker/端点的 config.json 和二进制软链由**控制面 WS 自动管理**:
- 手动改 config.json → 重启 → 控制面 WS 下发覆盖(还原)
- 版本升级也是控制面自动: 下载新版 → 创建 `zf-worker.new -> zf-worker-<版本>` 软链 → ExecStart 指向 .new

**结论**: 节点配置不要手动改, 以控制面为准。控制面改好(env/DB), 节点重启后自动同步。

### 检查 worker 实际版本(不是面板显示, 是真实上报)

```bash
# ① 在 worker 机器上直接查
/root/zf/zf-worker.new --version    # 输出 zfw-server 1.2.0 即 1.2.0
ls -la /root/zf/zf-worker*          # 看软链指向哪个版本文件
grep ExecStart /etc/systemd/system/zf.service  # 确认启动用的是哪个

# ② 在控制面查 controler 日志(worker 主动上报的版本)
docker logs zfc-controler | grep -aE "VersionReport from worker"
# 输出: recv VersionReport from worker 36: version=1.2.0  ← 真实版本

# ③ 面板 server-management 显示的就是 VersionReport 上报值(真实)
```

```bash
# controler 日志
```
